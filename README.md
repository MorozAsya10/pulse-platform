# Pulse — платформа онбординга (рабочий прототип)

Полноценное веб-приложение с backend (Python/Flask + SQLite), frontend (SPA на
чистом JS, без сборки) и тремя личными кабинетами:

- **Агентство Pulse** — создаёт компании-клиентов, приглашает их HR, видит
  сводку по всем компаниям.
- **HR-куратор компании** — приглашает сотрудников, выбирает формат программы
  (Preboarding / Onboarding / Postboarding), видит прогресс команды.
- **Сотрудник** — проходит адаптацию: чек-лист по дням/неделям/месяцу,
  геймификация (бейджи), мини-тест на знание компании, обратная связь.

Данные реально сохраняются в SQLite (`pulse.db`), авторизация — по
логину/паролю через JWT, доступ в систему — по персональным
ссылкам-приглашениям (агентство → HR → сотрудник).

## Запуск (2 команды, без сборки фронтенда)

Нужен Python 3.9+.

```bash
pip install -r requirements.txt
python3 app.py
```

Откройте **http://localhost:8000**

При первом запуске автоматически создаётся демо-компания «Кофе-точка» с
HR и тремя сотрудниками на разных стадиях адаптации — чтобы дашборды не
были пустыми. Демо-доступы (пароль один для всех — `pulse2026`):

## Как проверить полный сценарий

1. Войдите как агентство → создайте новую компанию → скопируйте
   ссылку-приглашение для HR.
2. Откройте эту ссылку (можно в новой вкладке/окне инкогнито — токен
   хранится в localStorage конкретного браузера) → задайте HR пароль.
3. В кабинете HR пригласите сотрудника, выбрав формат программы →
   скопируйте ссылку.
4. Откройте её (тоже в отдельном окне/инкогнито) → задайте пароль
   сотрудника → пройдите чек-лист, тест, оставьте обратную связь.
5. Вернитесь в кабинет HR и агентства и обновите страницу — прогресс
   сотрудника подтянется автоматически.

## Структура проекта

```
app.py         — Flask-приложение: все API-роуты (auth/agency/hr/employee)
db.py          — слой SQLite (схема, запросы)
auth.py        — JWT-аутентификация, декоратор require_auth(roles=[...])
templates.py   — шаблоны программ адаптации (Pre/Onboarding/Post) и мини-теста
seed.py        — демо-данные при первом запуске
static/        — фронтенд: index.html, app.js (SPA), styles.css
```

## Технические ограничения прототипа

Это MVP для демонстрации сценария, не production-система:

- Сервер разработки Flask (`app.run`) — для реальной эксплуатации нужен
  production-сервер (gunicorn/uwsgi) за реверс-прокси.
- SQLite — подходит для демо и небольшой нагрузки; для роста стоит
  перейти на Postgres.
- Секрет JWT задаётся переменной окружения `PULSE_JWT_SECRET` — на
  реальном хостинге обязательно задайте свой длинный случайный ключ.
- Ссылки-приглашения не имеют срока действия — для продакшена стоит
  добавить TTL.

## Деплой на Render (бесплатно, публичная ссылка)

Проект уже готов к деплою: есть `Procfile` (`web: gunicorn app:app`) и
`requirements.txt` с `gunicorn`. Шаги:

1. **Залейте папку в GitHub.** Проще всего — на github.com нажмите
   "New repository" (можно приватный), затем на странице пустого репо
   выберите "uploading an existing file" и перетащите туда всё
   содержимое папки `pulse-platform` (или используйте `git init && git
   add . && git commit -m "init" && git push`, если привычнее).
2. **Зарегистрируйтесь на [render.com](https://render.com)** — вход
   через GitHub, бесплатно, без карты.
3. **New → Web Service** → выберите только что созданный репозиторий.
4. Настройки сборки Render определит автоматически по `Procfile`, но
   на всякий случай:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
   - **Instance Type:** Free
5. В разделе **Environment** добавьте переменную
   `PULSE_JWT_SECRET` со своим случайным длинным значением (например,
   сгенерируйте командой `python3 -c "import secrets; print(secrets.token_hex(32))"`).
6. **Create Web Service** — через 1–2 минуты Render выдаст публичный
   адрес вида `https://pulse-platform.onrender.com` — это и есть
   рабочая ссылка, которую можно присылать клиентам.

Важно про бесплатный тариф Render: диск не постоянный, поэтому
`pulse.db` (и все данные) сбросятся при каждом передеплое или
"засыпании" сервиса из-за неактивности — это нормально для демо, но
для реальной эксплуатации переходите на платный план с постоянным
диском или на внешнюю Postgres-базу.

Если установите расширение Claude в Chrome и подключите его к этой
сессии — могу пройтись по шагам 1–6 вместе с вами прямо в браузере
(заполнить формы, нажать нужные кнопки), вход/подтверждение почты и
OAuth-разрешения всё равно нужно будет подтверждать вам самим.
